# Contributing

Thank you for contributing.

## Before starting

- Search existing Issues and Pull Requests to avoid duplicate work.
- For non-trivial changes, prefer an Issue that describes the problem and acceptance criteria.
- Follow the repository's `AGENTS.md` and project-specific documentation when present.

## Development

Use the commands and toolchain documented by the target repository. Do not introduce new frameworks, dependencies, or automation unless they solve a demonstrated project need.

## Pull requests

Keep changes focused and reviewable.

A Pull Request should:

- explain what changed and why;
- link the related Issue when one exists;
- record the validation actually performed;
- call out breaking changes, migrations, known risks, and follow-up work;
- update tests and documentation when behavior changes.

Do not claim checks passed if they were not run.
